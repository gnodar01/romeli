---

New feature: romeli "views"

We can view the set of all hieararchical tags as a tree, since it is essentially the same as a directory structure which is a tree of subdirectories.

The individual bookmarks are leafs of that tree. Although with hiearchical tags, the leafs can be duplicated across different paths in the tree.

Then a "view" is a filtered subset of hiearchical tags, forming a subtree.

The filtering can be done through two levels.

"vars" (variables) are boolean expressions of hierarchical tags (known as a "varsexpr").
The boolean operators are `!` for "not", `&` for "and", `|` for "or", `^` for "xor".

"views" are boolean expressions of hierarcical tags, and "vars" (known as a "viewsexpr").
The same boolean operators are used.
"vars" are referenced with curly braces, like so: "{varname}".

So for example we have this as our full romeli hierarchical tag tree in romeli on firefox:

root
    - toolbar/
    - menu/
    - tech/
        - languages/
            - python/
            - javascript/
            - c/
            - rust/
        - discussion/
            - hacker news/
            - lobsters/
        - videos/
        - linux/
    - media/
        - videos/
            - youtube/
        - articles/
            - news/
            - tech/

Then you might have a collection of "vars" (known as a "varset") like:

linux_discussions := 
      tech/linux/
    & tech/discussion/

linux_news :=
      tech/linux/
    & media/articles/tech/

compiled_langs :=
      tech/languages/c/
    + tech/languages/rust/

And you might have a collection of  "views" (known as a "viewset"), which reference either hieararchcial tags, or variables via "{var}" like:

linux :=
      {linux_discussions}
    | {linux_news}

scipting_langs :=
      tech/languages
    & ! {compiled_langs}

---

operator precedence is ! > & > ^ > +

there is no grouping operator such as parens. "vars" are the grouping mechanism. each "var" is a group, reusable across "views".

"viewset" and "varset" are separate, because "views" composed of other "views", would clutter things.
you may only want a small handful of "views" to choose from in the main menu, while they are composed of many more "vars" that are only inspectible in the editor (explained below).

---

NOTE: below all keybindings are defaults, that are overridable in settings

---

In main menu press "T" to open a dialog of existing views, where selecting one opens a new romeli tab of that view
    / - find view
    n/N - cycle through next/previous found view
    q - leave dialog
    j/k - navigate down/up through views
    f - filter views
    <esc> - cancel find, cancel filter
    v - vis mode
    V - unselect mode
    <enter> or o - open all selected (or single highlighted) in new romeli tab(s)
    <space> - toggle selection
    q - leave dialog

NOTE: care should be taken so that keybinds in this dialog do not propogate to main menu

In main menu press "K" to go to the viewset editor (explained below).

---

The editor contains the "viewset" editor and the "varset" editor.

The "varset" editor contains "vars" on the lefthand side column, and the highlighted "var"'s "tagsexpr" on the righthand side column.

The "viewset" editor contains "views" on the lefthand side column, and the highlighted "view"'s "varsexpr" on the righthand side column.

---

below is a rendering the layout of the editor. ">" is an indicator of where cursor focus is, i.e. whether it is in the "viewset" editor or the the "varset" editor, and for each whether it is in the "vars"/"views" column on the left or the "tagsexpr"/"varsexpr" on the right. "viewset" and "varset" are tabs in the top bar.

+=================+==================+
|   viewset       |     > varset     |
+=================+==================+
+-----------+------------------------+
| vars      | tagsexpr               |
+-----------+------------------------+
| > var1    |         [!] hier/tag/1 |
|   var2    |   (&^+) [!] hier/tag/2 |
|   ...     |           ...          |
+-----------+------------------------+

j - down to next var, cycle to top if at end
k - up to prev var, cycle to bottom if at beginning
l - go to tagsexpr editor for highlighted var
a - add new variable -> name? -> go to tagsexpr editor
r - rename
d - delete -> are you sure?
    highlighted item or all selected
y - yank
    only current highlighted item selected for yank, unselect previous item
    remains selected for yanked for as many puts, until <esc> or another is yanked
p - put (if yanked) -> name?
    as many times as desired until yank selection removed
v - vis mode
V - unselect mode
<space> - toggle select
/ - find var name
n/N - cycle found var names
f - filter var names
<esc> - deselect any selected, cancel "find", cancel any filters, back to normal mode
u - undo
<c-r> - redo
q - back to main menu
[ - go to viewset menu
